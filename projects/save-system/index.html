1. Project Overview

BeastySaveSystem es un plugin de Unity listo para producción que provee una solución completa de guardado orientada a plataformas móviles (Android / iOS) y escritorio (Windows / macOS / Linux). El sistema gestiona serialización de objetos, E/S de archivos cifrados con AES-256, gestión de slots de guardado con metadata, y una UI de demo completa construida con el patrón MVP.

1.1 Objetivos de Diseño

  • Zero boilerplate — Llama un método estático para guardar o cargar cualquier objeto. No se requieren atributos en las clases de datos.
  • Agnóstico de plataforma — Selección automática de ruta: persistentDataPath en mobile, dataPath en desktop.
  • Guardados cifrados — Cifrado AES-256 transparente al llamador; activado por un flag booleano.
  • Carga por referencia — Patrón PopulateObject que llena instancias existentes en lugar de crear nuevas — esencial para componentes de Unity.
  • Async-first — Cada API pública tiene un equivalente Task<T> async para E/S no bloqueante.
  • Soporte de tipos Unity — 21 conversores integrados para Transform, Colliders, Camera, Light, SpriteRenderer, Texture2D y todos los tipos de valor comunes.

  → Concrete Converter (ReadJson, existingValue)
  → existing object instance populated in-place ✓

2.4 Formato JSON — SaveByReference (typed envelope)

Al guardar con SaveRef o SaveRef_Encrypted, JsonSerializer envuelve el objeto para que DataProcessor pueda resolver la instancia destino correcta al cargar sin crear nuevos objetos:

{
  "objects": {
    "type": "Beasty_SaveSystem.SaveObjectModel",
    "data": {
      "PersistentID": "abc-123",
      "data": {
        "integerValue1": 42,
        "position1": { "x": 1.0, "y": 2.0, "z": 3.0 }
      },
      "exampleClass": { ... }
    }
  }
}

2.5 Formato JSON — SaveSystem (plain)

Usando Save / Load<T>, Newtonsoft.Json serializa el grafo de objetos directamente — sin envelope wrapper:

{
  "PersistentID": "abc-123",
  "data": {
    "Bounds": { "center": { "x":0,"y":0,"z":0 }, "size": { "x":1,"y":1,"z":1 } },
    "Color": { "r":1.0, "g":0.5, "b":0.0, "a":1.0 },
    "integerValue1": 42
  }
}

5. Encryption System

5.1 Algoritmo

El cifrado es provisto por la clase interna sealed Encrypted (namespace Beasty_SaveSystemCore). Usa System.Security.Cryptography.Aes de .NET:

ParámetroValor
AlgoritmoAES (Advanced Encryption Standard)
Longitud de clave256 bits — 32 bytes, codificados UTF-8 desde el string de la clave
ModoCBC (Cipher Block Chaining) — default de .NET AES
IV (Initialization Vector)16 bytes en cero — fijo por sesión
Codificación de salidaString Base64 escrito a disco
Soporte AsyncSí — EncryptAsync y DecryptAsync
⚠
Nota de seguridad — IV Fijo: El Initialization Vector siempre son 16 bytes en cero. Dos cifrados de texto idéntico con la misma clave producen ciphertext idéntico. Esto es aceptable para protección contra tampering en archivos de guardado, pero no es adecuado para seguridad semántica (e.g., transmisión en red). Para mayor protección, genera un IV aleatorio por guardado y prepéndelo al ciphertext antes de codificar en Base64.

5.2 PasswordGenerator

PasswordGenerator.GenerateSecurePassword(int length = 32) usa RNGCryptoServiceProvider para generar una clave aleatoria criptográficamente segura con caracteres alfanuméricos + símbolos.

// Genera una clave AES de 32 caracteres criptográficamente segura
string key = PasswordGenerator.GenerateSecurePassword(32);

// Asígnala a fileInfo (el setter aplica length == 32)
BeastySaveSystemFileSetup.Instance.fileInfo.EncryptionKey = key;

// IMPORTANTE: persiste la clave de forma segura (PlayerPrefs + derivación, keychain, servidor)
// Sin la clave original, los guardados cifrados no pueden descifrarse.

5.3 Decryption Guard

Antes de descifrar, Encrypted.Decrypt valida que el ciphertext sea Base64 válido via regex. Un string inválido lanza FormatException en lugar de retornar datos silenciosamente incorrectos — la excepción es capturada y logueada por el caller.

6. Converter System

Newtonsoft.Json no puede serializar nativamente la mayoría de los tipos Unity (Vector3, Transform, Colliders, etc.) porque tienen referencias circulares, estado interno oculto, o requieren instancias existentes para aplicar valores. El converter pipeline resuelve esto con un patrón strategy basado en registry.

6.1 IUnityTypeConverter Interface

public interface IUnityTypeConverter
{
    // Retorna true si este converter maneja objectType
    bool CanConvert(Type objectType);

    // Serializa value a JSON
    void WriteJson(JsonWriter writer, object value, JsonSerializer serializer);

    // Deserializa JSON y aplica a existingValue (no debe ser null para tipos componente)
    object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer);
}
ℹ
El parámetro existingValue en ReadJson es crítico. Los conversores de componentes (Transform, Colliders, Camera, Light, SpriteRenderer, MonoBehaviour, Texture2D) aplican valores a esta instancia existente en lugar de crear nuevos GameObjects. Si existingValue == null, loguean un Debug.LogError y retornan null — sin crash. Los conversores de tipos de valor (Vector2/3, Quaternion, Color, etc.) lo ignoran.

6.2 UnityObjectConverter & Registry

UnityObjectConverter (extiende JsonConverter) está registrado en JsonSettings y actúa como dispatcher. En WriteJson / ReadJson, itera UnityTypeConverterRegistry.Converters y delega al primer converter cuyo CanConvert retorne true. Si ningún converter hace match, cae al serializer.Serialize/Deserialize. Para GameObject específicamente, refleja propiedades públicas omitiendo las obsoletas y circulares.

10. DataProcessor — Type-Safe In-Place Loading

DataProcessor es el motor estático interno que conecta el formato JSON de typed-envelope con instancias de objetos existentes. Llamado exclusivamente por SaveByReference.Load y SaveSystem_List.LoadAndAssign.

10.1 ProcessLoadedData(string json, object target) — Single Object

  1. Parse del string JSON en un JObject.
  2. Extracción del token "objects" — soporta tanto JObject como JArray.
  3. Lectura del campo "type" y resolución del tipo CLR completo via ResolveType (escanea todos los assemblies del AppDomain).
  4. Comparación del tipo resuelto contra target.GetType().
  5. En match: llama JsonConvert.PopulateObject(data.ToString(), target, JsonSettings) — aplica valores in-place a la instancia existente.
  6. Loguea un warning si no se encuentra tipo coincidente.

10.2 ProcessLoadedData(string json, List<object> list) — List

  1. Deserializa el JSON en Dictionary<string, object>.
  2. Cast de "objects" a JArray.
  3. Para cada elemento: resuelve tipo, encuentra la primera instancia coincidente en objectList por tipo.
  4. Llama PopulateObject en cada instancia matched.
  5. Omite elementos con tipos no resolvibles o sin entrada coincidente — loguea un warning, no lanza excepción.

10.3 ResolveType(string typeName)

Busca en todos los assemblies en AppDomain.CurrentDomain.GetAssemblies() el nombre de tipo fully-qualified. Retorna null si no se encuentra. Maneja tipos a través de Unity runtime, game scripts, y plugins sin registro explícito.

// Tipo almacenado en JSON: "Beasty_SaveSystem.SaveObjectModel"
Type t = DataProcessor.ResolveType("Beasty_SaveSystem.SaveObjectModel");
// Retorna el Tipo CLR si se encuentra en algún assembly cargado, null de lo contrario

La ruta final de guardado se construye como:

12. Integration Guide

12.1 Scene Setup

  1. Crea un GameObject vacío en tu escena persistente (e.g., SaveSystem).
  2. Adjunta BeastySaveSystemFileSetup. Configura campos de fileInfo en el Inspector (extensión, carpeta, clave de cifrado).
  3. Adjunta SaveSlotController al mismo GameObject o a uno hermano.
  4. Activa Enable Encrypt para habilitar archivos de guardado AES-256.
  5. Activa Enable Logs para output de debug en consola durante desarrollo (desactivar en release).

14. Known Limitations & Recommendations

IV Fijo en Cifrado AES

El IV siempre son 16 bytes en cero. Dos guardados con el mismo plaintext y clave producen ciphertext idéntico. Para mayor protección, genera un IV aleatorio por guardado y prepéndelo al ciphertext antes de Base64, luego léelo de vuelta durante el descifrado.

Escaneo de AppDomain Assembly en cada Carga

DataProcessor.ResolveType itera todos los assemblies cargados en cada llamada. Para proyectos grandes, considera cachear tipos resueltos en un Dictionary<string, Type> para evitar escaneos repetidos.

Referencia de Asset Sprite No Guardada

SpriteRendererConverter guarda propiedades de renderizado (color, flip, sorting) pero no la referencia del asset Sprite. Guarda la clave Addressables del sprite o la ruta de Resources por separado y re-asigna al cargar.

Asset de Mesh No Guardado

MeshColliderConverter guarda flags convex/trigger pero no el asset de mesh. Usa un registro de mesh por nombre si se necesita re-asignación de mesh al cargar.

Match de Tipo Único por Lista

SaveSystem_List encuentra el primer objeto en la lista que coincide con un tipo dado. Múltiples objetos del mismo tipo en una lista recibirán todos los datos de la primera entrada coincidente. Usa un diccionario keyed por tipo o clases wrapper únicas como workaround.

Sin API de Delete Slot

ConfigFile.Remove elimina la entrada de metadata, pero el archivo de guardado físico debe eliminarse por separado via File.Delete(info.GetFullPath(metadata.FileName)).

DataPath en Editor vs. Build

En el Unity Editor, Application.dataPath apunta a la carpeta Assets. En un build de escritorio apunta dentro del directorio de build, que puede ser read-only en algunos sistemas. Considera override de DataPath a Application.persistentDataPath para builds de escritorio en release.

15. Quick Reference Card

Árbol de Decisión — ¿Qué API usar?

P: ¿El objeto hereda de MonoBehaviour o Component?
   SÍ  ──→ Usa SaveRef / LoadRef  (reference-based, in-place)
   NO  ──→
       P: ¿Un solo objeto?
          SÍ  ──→ Usa Save / Load<T>
          NO  ──→ Usa Save_ObjectList / LoadAndMergeList

P: ¿Necesitas cifrado?
   SÍ  ──→ Agrega _Encrypted al nombre del método
   NO  ──→ Usa la versión plain

P: ¿Puede el caller bloquear el main thread?
   SÍ  ──→ Usa versiones síncronas (sin sufijo Async)
   NO  ──→ Usa versiones async (sufijo Async) con await

Convención de Nombres de Métodos

Sufijo / PrefijoSignificado
AsyncRetorna Task<T> — usar con await. E/S no bloqueante.
_EncryptedAES-256 cifrado al guardar / descifrado al cargar. Clave desde SaveFileInfo.EncryptionKey.
Ref / LoadRefReference-based — llena una instancia existente. Requerido para MonoBehaviours.
_ObjectListOpera en List<object> con tipos mixtos.
LoadAndMergeMerge de datos cargados en elementos existentes de la lista (in-place por elemento).
