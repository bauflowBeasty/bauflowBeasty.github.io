1. Project Overview

BeastySaveSystem is a production-ready Unity plugin that provides a complete save solution targeting mobile platforms (Android / iOS) and desktop (Windows / macOS / Linux). The system handles object serialization, AES-256 encrypted file I/O, save-slot management with metadata, and a full demo UI built with the MVP pattern.

1.1 Design Goals

  • Zero boilerplate — Call a static method to save or load any object. No attributes required on data classes.
  • Platform-agnostic — Automatic path selection: persistentDataPath on mobile, dataPath on desktop.
  • Encrypted saves — AES-256 encryption transparent to the caller; enabled by a boolean flag.
  • Load by reference — PopulateObject pattern fills existing instances instead of creating new ones — essential for Unity components.
  • Async-first — Every public API has a Task<T> async equivalent for non-blocking I/O.
  • Unity type support — 21 built-in converters for Transform, Colliders, Camera, Light, SpriteRenderer, Texture2D and all common value types.

2.2 Data Flow — Save Operation

Caller
  → BeastySaveSystemAPI (static facade)
  → SaveSystem / SaveByReference / SaveSystem_List
  → JsonConvert.SerializeObject + JsonSettings
  → UnityObjectConverter
  → UnityTypeConverterRegistry (converter lookup)
  → Concrete Converter (WriteJson)
  → JSON string
  → [optional] Encrypted.Encrypt()
  → FileOperationsHandler.WriteToFile / WriteToFileAsync

2.3 Data Flow — Load (Reference) Operation

Caller
  → BeastySaveSystemAPI.LoadRef / LoadRef_Encrypted
  → SaveByReference.Load()
  → FileOperationsHandler.ReadFromFile
  → [optional] Encrypted.Decrypt()
  → DataProcessor.ProcessLoadedData()
  → JObject.Parse → type resolution via ResolveType()
  → JsonConvert.PopulateObject + JsonSettings
  → UnityObjectConverter
  → Concrete Converter (ReadJson, existingValue)
  → existing object instance populated in-place ✓

2.4 JSON Format — SaveByReference (typed envelope)

When saving with SaveRef or SaveRef_Encrypted, the JsonSerializer wraps the object so DataProcessor can resolve the correct target instance when loading without creating new objects:

{
  "objects": {
    "type": "Beasty_SaveSystem.SaveObjectModel",
    "data": {
      "PersistentID": "abc-123",
      "data": {
        "integerValue1": 42,
        "position1": { "x": 1.0, "y": 2.0, "z": 3.0 }
      },
      "exampleClass": { ... }
    }
  }
}

2.5 JSON Format — SaveSystem (plain)

Using Save / Load<T>, Newtonsoft.Json serializes the object graph directly — no envelope wrapper:

{
  "PersistentID": "abc-123",
  "data": {
    "Bounds": { "center": { "x":0,"y":0,"z":0 }, "size": { "x":1,"y":1,"z":1 } },
    "Color": { "r":1.0, "g":0.5, "b":0.0, "a":1.0 },
    "integerValue1": 42
  }
}

3. Core Classes Reference

SaveFileInfo is a serializable configuration container passed to every save/load operation.

PropertyTypeDefaultDescription

5. Encryption System

5.1 Algorithm

Encryption is provided by the internal sealed class Encrypted (namespace Beasty_SaveSystemCore). Uses System.Security.Cryptography.Aes from .NET:

ParameterValue
AlgorithmAES (Advanced Encryption Standard)
Key length256 bits — 32 bytes, UTF-8 encoded from the key string
ModeCBC (Cipher Block Chaining) — .NET AES default
IV (Initialization Vector)16 zero bytes — fixed per session
Output encodingBase64 string written to disk
Async supportYes — EncryptAsync and DecryptAsync
⚠
Security Note — Fixed IV: The Initialization Vector is always 16 zero bytes. Two encryptions of identical plaintext with the same key produce identical ciphertext. This is acceptable for tamper protection on save files, but is not suitable for semantic security (e.g., network transmission). For stronger protection, generate a random IV per save and prepend it to the ciphertext before Base64 encoding.

5.2 PasswordGenerator

PasswordGenerator.GenerateSecurePassword(int length = 32) uses RNGCryptoServiceProvider to generate a cryptographically secure random key with alphanumeric + symbol characters.

// Generate a cryptographically secure 32-character AES key
string key = PasswordGenerator.GenerateSecurePassword(32);

// Assign to fileInfo (setter enforces length == 32)
BeastySaveSystemFileSetup.Instance.fileInfo.EncryptionKey = key;

// IMPORTANT: persist the key securely (PlayerPrefs + derivation, keychain, server)
// Without the original key, encrypted saves cannot be decrypted.

5.3 Decryption Guard

Before decrypting, Encrypted.Decrypt validates that the ciphertext is valid Base64 via regex. An invalid string throws FormatException instead of silently returning incorrect data — the exception is caught and logged by the caller.

6. Converter System

Newtonsoft.Json cannot natively serialize most Unity types (Vector3, Transform, Colliders, etc.) because they have circular references, hidden internal state, or require existing instances to apply values. The converter pipeline resolves this with a registry-based strategy pattern.

6.1 IUnityTypeConverter Interface

public interface IUnityTypeConverter
{
    // Returns true if this converter handles objectType
    bool CanConvert(Type objectType);

    // Serialize value to JSON
    void WriteJson(JsonWriter writer, object value, JsonSerializer serializer);

    // Deserialize JSON and apply to existingValue (must not be null for component types)
    object ReadJson(JsonReader reader, Type objectType, object existingValue, JsonSerializer serializer);
}
ℹ
The existingValue parameter in ReadJson is critical. Component converters (Transform, Colliders, Camera, Light, SpriteRenderer, MonoBehaviour, Texture2D) apply values to this existing instance instead of creating new GameObjects. If existingValue == null, they log a Debug.LogError and return null — no crash. Value type converters (Vector2/3, Quaternion, Color, etc.) ignore it.

6.2 UnityObjectConverter & Registry

UnityObjectConverter (extends JsonConverter) is registered in JsonSettings and acts as a dispatcher. In WriteJson / ReadJson, it iterates UnityTypeConverterRegistry.Converters and delegates to the first converter whose CanConvert returns true. If no converter matches, it falls back to serializer.Serialize/Deserialize. For GameObject specifically, it reflects public properties omitting obsolete and circular ones.

7. Save Slot System

The slot system provides named save files with rich metadata, supporting overwrites and incremental slot numbering. It is built on the core API and uses the reference-based format for all slot data.

7.1 SaveSlotController

Singleton MonoBehaviour. Coordinates slot creation, slot index persistence, and UI card instantiation. Reads the global encryption toggle from BeastySaveSystemFileSetup.Instance.EnableEncryt.

MethodDescription
Save(SaveObjectModel, displayName?, metadata?, OnSuccess?, OnError?)Dispatches to SaveSlot or SaveSlotEncrypted based on the global encryption flag.
SaveSlot(...)Creates or reuses metadata, adds it to ConfigFile, saves slot data via SaveRef, then saves ConfigFile.
SaveSlotEncrypted(...)Same flow but uses SaveRef_Encrypted for slot data and Save_Encrypted for ConfigFile.
LoadConfigFile()Loads the ConfigFile (slot index) from disk into the configFile field.
CreateSlotsCards(GameObject card, Transform parent)Calls LoadConfigFile, destroys old cards, then instantiates one UI card prefab per slot entry.
LoadSlotFile(Metadata)Returns a SaveObjectModel deserialized from the slot file (new instance).
LoadSlotFile<T>(Metadata, T target)Fills an existing T instance via LoadRef / LoadRef_Encrypted.
CreateMetadataForSaveSlot(displayName)Auto-numbers slots by counting Slot*.ext files in the save folder via FileFinder.
DestroyAllChildren(Transform parent)Destroys child GameObjects in reverse order to avoid index issues.

7.2 ConfigFile

The slot index — a serializable class containing a List<Metadata>. Saved as a standard file named ConfigFile in the same folder as slot files.

10. DataProcessor — Type-Safe In-Place Loading

DataProcessor is the internal static engine that connects the typed-envelope JSON format with existing object instances. Called exclusively by SaveByReference.Load and SaveSystem_List.LoadAndAssign.

10.1 ProcessLoadedData(string json, object target) — Single Object

  1. Parse the JSON string into a JObject.
  2. Extract the "objects" token — supports both JObject and JArray.
  3. Read the "type" field and resolve the full CLR type via ResolveType (scans all AppDomain assemblies).
  4. Compare the resolved type against target.GetType().
  5. On match: call JsonConvert.PopulateObject(data.ToString(), target, JsonSettings) — applies values in-place to the existing instance.
  6. Logs a warning if no matching type is found.

10.2 ProcessLoadedData(string json, List<object> list) — List

  1. Deserialize JSON into Dictionary<string, object>.
  2. Cast "objects" to JArray.
  3. For each element: resolve type, find first matching instance in objectList by type.
  4. Call PopulateObject on each matched instance.
  5. Skips elements with unresolvable types or no matching entry — logs a warning, does not throw.

10.3 ResolveType(string typeName)

Searches all assemblies in AppDomain.CurrentDomain.GetAssemblies() for the fully-qualified type name. Returns null if not found. Handles types across Unity runtime, game scripts, and plugins without explicit registration.

// Type stored in JSON: "Beasty_SaveSystem.SaveObjectModel"
Type t = DataProcessor.ResolveType("Beasty_SaveSystem.SaveObjectModel");
// Returns the CLR Type if found in any loaded assembly, null otherwise

11. Platform Support & File Paths

PlatformDefault Base PathNotes
Windows / macOS / LinuxApplication.dataPathIn editor: points to Assets folder. In build: inside build directory. May be read-only on some systems.
AndroidApplication.persistentDataPathApp sandbox. Survives reinstall on most devices. Path set by preprocessor directive.
iOSApplication.persistentDataPathApp sandbox. Eligible for iCloud backup. Path set by preprocessor directive.

The final save path is built as:

{DataPath} / {SaveFolder} / {FileName}.{FileExtension}

GetFullPath auto-creates the directory via Directory.CreateDirectory if it doesn't exist. Both SaveFileInfo and BaseSaveFileInfo use identical preprocessor directives to determine the platform default.

⚠
For desktop builds, consider overriding DataPath to Application.persistentDataPath if the installation directory may be read-only (common in protected system folders on Windows/macOS).

12. Integration Guide

12.1 Scene Setup

  1. Create an empty GameObject in your persistent scene (e.g., SaveSystem).
  2. Attach BeastySaveSystemFileSetup. Configure fileInfo fields in the Inspector (extension, folder, encryption key).
  3. Attach SaveSlotController to the same or a sibling GameObject.
  4. Enable Enable Encrypt to activate AES-256 save files.
  5. Enable Enable Logs for debug console output during development (disable in release).

12.2 Saving Your Data

SaveFileInfo info = BeastySaveSystemFileSetup.Instance.fileInfo;

// Option A: Plain C# class — use Save / Load<T>
var pd = new PlayerData { integerValue1 = 42 };
BeastySaveSystemAPI.Save(pd, "player", info);
PlayerData result = BeastySaveSystemAPI.Load<PlayerData>("player", info);

// Option B: MonoBehaviour — use SaveRef / LoadRef
BeastySaveSystemAPI.SaveRef(myMono, "player_component", info);
BeastySaveSystemAPI.LoadRef("player_component", myMono, info);  // in-place

// Option C: Save slot with metadata
SaveSlotController.Instance.Save(saveObjectModel, displayName: "Slot 1",
    OnSuccess: () => Debug.Log("Saved!"),
    OnError:   () => Debug.LogError("Error!"));

12.3 Custom Encryption Key

string key = PasswordGenerator.GenerateSecurePassword(32);
BeastySaveSystemFileSetup.Instance.fileInfo.EncryptionKey = key;

// Persist the key securely — without it, encrypted saves cannot be decrypted
PlayerPrefs.SetString("save_key", key);  // example only — use a secure store

12.4 Adding a Custom Converter

// Step 1: Implement IUnityTypeConverter
internal sealed class MyTypeConverter : IUnityTypeConverter
{
    public bool CanConvert(Type t) => t == typeof(MyUnityType);

    public void WriteJson(JsonWriter w, object val, JsonSerializer s)
    {
        var obj = (MyUnityType)val;
        w.WriteStartObject();
        w.WritePropertyName("myField");
        w.WriteValue(obj.myField);
        w.WriteEndObject();
    }

    public object ReadJson(JsonReader r, Type t, object existing, JsonSerializer s)
    {
        if (existing == null)
        {
            Debug.LogError("[MyTypeConverter] existingValue is null.");
            return null;
        }
        var target = (MyUnityType)existing;
        // ... read properties from reader and apply to target ...
        return target;
    }
}

// Step 2: Register in UnityTypeConverterRegistry.Converters — add BEFORE GenericObjectConverter (which acts as fallback)

14. Known Limitations & Recommendations

Fixed IV in AES Encryption

The IV is always 16 zero bytes. Two saves with the same plaintext and key produce identical ciphertext. For stronger protection, generate a random IV per save and prepend it to the ciphertext before Base64, then read it back during decryption.

AppDomain Assembly Scan on Every Load

DataProcessor.ResolveType iterates all loaded assemblies on every call. For large projects, consider caching resolved types in a Dictionary<string, Type> to avoid repeated scans.

Sprite Asset Reference Not Saved

SpriteRendererConverter saves rendering properties (color, flip, sorting) but not the Sprite asset reference. Save the sprite's Addressables key or Resources path separately and re-assign on load.

Mesh Asset Not Saved

MeshColliderConverter saves convex/trigger flags but not the mesh asset. Use a mesh registry keyed by name if mesh re-assignment is needed on load.

Single Type Match per List

SaveSystem_List finds the first object in the list that matches a given type. Multiple objects of the same type in a list will all receive data from the first matching entry. Use a type-keyed dictionary or unique wrapper classes as a workaround.

No Delete Slot API

ConfigFile.Remove removes the metadata entry, but the physical save file must be deleted separately via File.Delete(info.GetFullPath(metadata.FileName)).

DataPath in Editor vs. Build

In the Unity Editor, Application.dataPath points to the Assets folder. In a desktop build it points inside the build directory, which may be read-only on some systems. Consider overriding DataPath to Application.persistentDataPath for release desktop builds.

15. Quick Reference Card

Decision Tree — Which API to Use?

Q: Does the object inherit from MonoBehaviour or Component?
   YES ──→ Use SaveRef / LoadRef  (reference-based, in-place)
   NO  ──→
       Q: Single object?
          YES ──→ Use Save / Load<T>
          NO  ──→ Use Save_ObjectList / LoadAndMergeList

Q: Do you need encryption?
   YES ──→ Add _Encrypted to the method name
   NO  ──→ Use the plain version

Q: Can the caller block the main thread?
   YES ──→ Use sync versions (no Async suffix)
   NO  ──→ Use async versions (Async suffix) with await

Method Naming Convention

Suffix / PrefixMeaning
AsyncReturns Task<T> — use with await. Non-blocking I/O.
_EncryptedAES-256 encrypted on save / decrypted on load. Key from SaveFileInfo.EncryptionKey.
Ref / LoadRefReference-based — fills an existing instance. Required for MonoBehaviours.
_ObjectListOperates on List<object> with mixed types.
LoadAndMergeMerges loaded data into existing list elements (in-place per element).
