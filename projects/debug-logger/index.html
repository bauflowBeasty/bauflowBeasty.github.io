1. Overview

BeastyDebugLogger is a drop-in logging library for Unity projects. It wraps Unity's built-in Debug class and adds:

  • Twelve semantic log levels, each with a distinct emoji prefix and color.
  • A single master switch to silence all output in release builds.
  • Per-call conditional printing — pass any boolean to gate a specific log.
  • A custom Beasty Console Window in the Unity Editor with filtering, search, collapse mode, and one-click IDE navigation.
ℹ️ Editor vs. Build Colors and the Beasty Console window are editor-only. In standalone builds, all output is plain text routed through Unity's standard log system — no extra overhead.

2. Setup

2a. Namespace

All API calls live under the BeastyDebugLoggerConsole namespace. Add a using directive at the top of any script that logs: 

using BeastyDebugLoggerConsole;

The class itself is static — no instance, no MonoBehaviour, no initialization needed. Just call its methods directly: 

BeastyDebugLogger.LogInfo("Game started!");

2b. Master Switch — IsEnabled

A single static boolean controls all output at once. Set it to false to silence every log call across your entire project without removing or commenting out any code: 

// Disable all BeastyDebugLogger output (e.g. in release builds)
BeastyDebugLogger.IsEnabled = false;
✅ Recommended pattern Set IsEnabled = !Application.isEditor or tie it to a debug build flag so logs are automatically suppressed in production.
Per-call gate Every method also accepts a canPrint parameter (see below) which acts as a local switch for that specific call, independently of IsEnabled. Both conditions must be true for a message to appear.

3. Public API Reference

3a. Log — Generic

The base method. Use it when you want to specify the color manually via the LogColor enum, or when you simply want a plain unstyled message.

📝 void Log(string message, bool canPrint = true, Object context = null)

Logs a plain message with no color or emoji applied.

ParameterTypeDefaultDescription
messagestring—The text to output.
canPrintbooltrueLocal gate. Pass false to suppress this specific call.
contextObjectnullUnity Object to associate with this log entry (click in Console to ping it).
🎨 void Log(string message, LogColor color, bool canPrint = true, Object context = null)

Overload with a color. In the editor the message will appear in the corresponding color inside the Beasty Console. In builds, color is stripped and the message is plain text.

ParameterTypeDefaultDescription
messagestring—The text to output.
colorLogColor—One of the values from the LogColor enum.
canPrintbooltrueLocal gate.
contextObjectnullUnity context object.

3c. PrintLongMessage

📄 void PrintLongMessage(string message, int chunkSize = 9999, bool canPrint = true, string label = "")

Unity's console truncates messages that exceed its internal character limit. Use this method to safely output very long strings — it splits the content into numbered chunks and logs each one as a separate LogHighlight entry.

ParameterTypeDefaultDescription
messagestring—The full text to output, regardless of length.
chunkSizeint9999Maximum characters per log entry.
canPrintbooltrueLocal gate.
labelstring""Tag prepended to each chunk for easier identification in the console.

Each chunk appears in the console prefixed with its starting character index and the label:

// For a 25 000-character JSON blob:
BeastyDebugLogger.PrintLongMessage(jsonBlob, label: "SaveData");

// Console output:
// ✨ 0.SaveData: {"player":{"level":7, ...
// ✨ 9999.SaveData: ..."inventory":[{ ...
// ✨ 19998.SaveData: ...],"achievements"...

4. Beasty Console Window

The Beasty Console is a custom Unity Editor window that displays logs sent through BeastyDebugLogger with full color-coding, per-type filtering, search, and direct code navigation. It works alongside Unity's built-in Console — you can use both simultaneously.

Editor Only

4a. Opening the Window

From the Unity menu bar:

Window → Beasty → Beasty Console

The window is freely dockable — drag it next to Unity's built-in Console or anywhere else in your layout.

4b. Main Toolbar

ControlDescription
Clear Removes all log entries from the window. Does not affect Unity's built-in Console.
Collapse When active, consecutive identical messages are merged into one row. A counter badge on the right shows how many times that message was logged. Useful for high-frequency logs (e.g. per-frame updates) that would otherwise flood the list.
Clear on Play When active, the log list is automatically cleared each time you press Play in the Editor.
Error Pause When active, Play Mode is automatically paused the moment a LogError or LogException entry is received.
Search field Type any text to filter log rows in real time. Only entries whose message contains the search string (case-insensitive) will be shown. Clear the field to show all entries.

4c. Filter Bar

Below the main toolbar is a scrollable row of filter buttons — one per log type. Each button shows the type's emoji, its name, and the current count of entries of that type.

  • Click a button to toggle that log type on or off in the list.
  • Active types are highlighted in their own color. Inactive types are dimmed.
  • Counts update live as new logs arrive.
  • The filter bar can be scrolled horizontally if the window is narrow.
✅ Tip Turn off Verbose and Trace during active debugging to focus on Debug, Caution, Warning, and Error.

4d. Log List

The main area shows filtered log entries as a scrollable list. Each row displays:

  • Emoji icon — instantly identifies the log type at a glance.
  • Timestamp — time since Play Mode began (mm:ss.mmm format).
  • Message text — shown in the log type's color.
  • Count badge — visible only when Collapse mode is on, showing how many times the message repeated.

Single-click a row to select it and see its full message and stack trace in the Detail Panel below. Double-click a row to jump directly to the originating line in your code editor.

4e. Detail Panel

The lower portion of the window shows details for the currently selected log entry.

  • The full message text is displayed in a selectable area — you can copy it with Ctrl+A then Ctrl+C.
  • The stack trace is shown below the message, one line per frame.
  • Lines that reference source files in your project appear as clickable links (underlined) — click one to open that file at the exact line in your IDE.

A draggable splitter handle sits between the log list and the detail panel. Drag it up or down to adjust how much vertical space each area receives.

4f. IDE Navigation

The Beasty Console integrates with your code editor (Visual Studio, Rider, VS Code) for seamless navigation:

  • Double-click a log row — opens the source file and positions the cursor at the line that called BeastyDebugLogger. The window automatically skips internal framework frames and takes you to your code.
  • Click a stack trace link in the Detail Panel — opens the exact frame you clicked, whether it's your code or a library.
ℹ️ Note IDE navigation uses Unity's standard file-opening mechanism, so whichever editor Unity is configured to use (set in Edit → Preferences → External Tools) is the one that will open.

5. Editor vs. Builds

IsEnabled Respected — set to false to silence in editor too Respected — recommended to set false in production
canPrint parameter Respected per-call Respected per-call
Performance overhead Minimal — color formatting is a string concat Minimal — Colorize() is a no-op in non-editor builds

7. Code Examples

Basic Usage

using BeastyDebugLoggerConsole;

public class PlayerController : MonoBehaviour
{
    private void Start()
    {
        BeastyDebugLogger.LogInfo("PlayerController initialized");
    }

    private void OnLevelUp(int newLevel)
    {
        BeastyDebugLogger.LogSuccess($"Player reached level {newLevel}!");
    }

    private void Update()
    {
        // canPrint gates this without removing the line
        BeastyDebugLogger.LogVerbose($"Position: {transform.position}", canPrint: IsDebugging());
    }
}

Using the canPrint Gate

// Log only when a condition is true — no if-block needed
BeastyDebugLogger.LogDebug($"Inventory slots used: {usedSlots}", canPrint: showInventoryLogs);

// Log only in the editor
BeastyDebugLogger.LogTrace("Entering Save coroutine", canPrint: Application.isEditor);

Disabling All Logs in Release

private void Awake()
{
    // Silence everything in production builds
    BeastyDebugLogger.IsEnabled = Debug.isDebugBuild;
}

Logging Exceptions

try
{
    await saveManager.WriteAsync(slot);
    BeastyDebugLogger.LogSuccess($"Save slot {slot} written.");
}
catch (System.Exception e)
{
    BeastyDebugLogger.LogException(e);
    BeastyDebugLogger.LogError($"Failed to write save slot {slot}.");
}

Printing a Long JSON Payload

string json = JsonUtility.ToJson(playerData, prettyPrint: true);
BeastyDebugLogger.PrintLongMessage(json, chunkSize: 8000, label: "PlayerData");

Using Generic Log with a Custom Color

// Apply a specific color from the enum
BeastyDebugLogger.Log("Custom styled message", BeastyDebugLogger.LogColor.Highlight);

// Plain white — useful when you want no semantic color
BeastyDebugLogger.Log("Raw output", BeastyDebugLogger.LogColor.Plain);

Context Object (clicking pings in the Hierarchy)

// Pass the offending GameObject as context
BeastyDebugLogger.LogError("Missing collider component!", context: this.gameObject);
