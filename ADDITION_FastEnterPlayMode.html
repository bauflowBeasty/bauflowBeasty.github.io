🐾 BeastyDebugLogger — Adición a la documentación

Compatibilidad con Fast Enter Play Mode (Unity 6.6+) · Para añadir al User Guide publicado en la web · Junio 2026

A partir de la versión actual, BeastyDebugLogger.IsEnabled se reinicia automáticamente a true al comienzo de cada sesión de Play, incluso con domain reload desactivado (Fast Enter Play Mode, el ajuste por defecto desde Unity 6.6). Hay que documentar este comportamiento en dos puntos de la página del User Guide.

1. Añadir un callout en la sección 2b. Master Switch — IsEnabled

📍 Dónde va En la sección 2. Setup → 2b. Master Switch — IsEnabled, justo después del callout morado que dice "Per-call gate" (es el último elemento de esa sección, antes de la línea divisoria que da paso a la sección 3).

Vista previa de cómo quedará:

ℹ️ Fast Enter Play Mode (Unity 6.6+) IsEnabled automatically resets to true at the start of every Play session — even when domain reload is disabled (Fast Enter Play Mode, the default since Unity 6.6). This means you cannot "set it once" in a previous session and expect the value to persist: if you want logs disabled, set IsEnabled = false in your own initialization code (e.g. in Awake()), which runs after the reset.

Código HTML listo para copiar y pegar (usa las mismas clases CSS que ya existen en la página):

<div class="callout callout-info">
  <strong>ℹ️ Fast Enter Play Mode (Unity 6.6+)</strong>
  <code>IsEnabled</code> automatically resets to <code>true</code> at the start of every
  Play session — even when domain reload is disabled (Fast Enter Play Mode, the default
  since Unity 6.6). This means you cannot "set it once" in a previous session and expect
  the value to persist: if you want logs disabled, set <code>IsEnabled = false</code> in
  your own initialization code (e.g. in <code>Awake()</code>), which runs after the reset.
</div>

2. Actualizar la fila IsEnabled de la tabla en la sección 5. Editor vs. Builds

📍 Dónde va En la sección 5. Editor vs. Builds hay una tabla comparativa. Sustituir el contenido de la fila cuyo primer campo es IsEnabled.

Vista previa de la fila actualizada (solo cambia el texto de la columna Editor):

3. (Opcional) Entrada de changelog

Si la web tiene sección de changelog / release notes, añadir esta línea a la versión actual: 

Fixed: IsEnabled now resets correctly between Play sessions when
Fast Enter Play Mode (domain reload disabled) is active. (Unity 6.6+ compatible)

Contexto técnico (por si hay dudas)

  • Desde Unity 6.6, Fast Enter Play Mode es el ajuste por defecto: los campos static conservan su valor entre sesiones de Play porque no hay recarga de dominio.
  • Antes de este cambio, si un usuario ponía IsEnabled = false durante el Play, el valor sobrevivía a la siguiente sesión y los logs "desaparecían" sin explicación.
  • Ahora el plugin lo resetea con [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)], que se ejecuta al inicio de cada Play, antes de cualquier Awake() del usuario — por eso el patrón recomendado (desactivarlo en Awake) sigue funcionando igual.
  • El resto de estáticos del paquete (tablas de colores, regexes de la ventana del editor) son readonly e inmutables, así que no necesitan documentación.
